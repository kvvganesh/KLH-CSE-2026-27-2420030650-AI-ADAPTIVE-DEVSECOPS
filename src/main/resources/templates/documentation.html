Project overview

Adaptive DevSecOps Pipeline for Intelligent Vulnerability Assessment and Secure Deployment is a demonstration platform. It combines the results of four security tools into one risk score and uses that score to decide whether a release may be deployed.

Problem statement

Security tools produce separate reports that teams read late or inconsistently. Pipelines then either ignore findings or fail on every warning. This project turns the signals into one explainable decision that adapts to the actual risk.

How the pipeline works

Source→Build→JUnit→SonarQube→Gitleaks→OWASP→Risk analysis→Deployment decision

The real workflow lives in .github/workflows/devsecops.yml. The web application simulates a run so the full flow can be demonstrated offline with three fixed scenarios.

Security tools

  • JUnit: unit and security tests of the application.
  • SonarQube: code quality, bugs, code vulnerabilities and the quality gate.
  • Gitleaks: detects secrets committed to the repository.
  • OWASP Dependency-Check: finds dependencies with known vulnerabilities.

Risk assessment

An explainable rule-based engine (not machine learning). Each signal adds points: critical secret +50, critical dependency +50, high +25, medium +15, quality gate failure +15, failed tests +10. The total is capped at 100. LOW is 0–29, MEDIUM 30–59, HIGH 60 and above.

Adaptive deployment

LOWDeployment approved
MEDIUMSecurity review required
HIGHDeployment blocked

Deployments are simulated. Nothing is released anywhere.

Technology stack

Java 21, Spring Boot 4, Maven, Thymeleaf, HTML/CSS/JavaScript, JUnit, SonarQube, Gitleaks, OWASP Dependency-Check, Git, GitHub and GitHub Actions. Data is held in memory, so no database is needed.

Architecture

Browser (Thymeleaf pages + app.js)→Controllers (pages + REST API)→Services→Repositories→Models

Pages are rendered by PageController. Actions (run pipeline, add project, switch scenario, simulate deployment, download report) call the REST API under /api.
